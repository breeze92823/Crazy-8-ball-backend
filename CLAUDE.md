# Crazy 8 Ball — BACKEND (game server)

Frontend (3D rooftop pool client) lives at `../Crazy-8-ball`. Colyseus + Mongo, ported from the Bowling Roll backend. Project rules (public repos, no premium-currency purchases) are in `../CLAUDE.md`.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest` / `test/fakePlayers.ts`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, pose?, loadout?, avatar? })`). Client-authoritative save: the server only bounds/sanitises it (`src/sanitize.ts`). Server-authoritative: spin wheel, Daily Reward + streak track, playtime gifts. `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The client keeps NO progress in the browser: this server's Mongo doc is the player's only save. A guest's (or a serverless session's) progress, daily, track and gifts last the connection only (in memory).
- Load / identity: on join and on `identify` { userId, username, pfp } (sign-in/out mid-session) the server answers privately `progress` { ...saved fields (sanitized), serverTime } or `noProgress` { serverTime } (new account, guest, no database: the client keeps its fresh state and saves it), then `spins`, `gifts`, `daily`, `leaderboard`. A failed read sends `serverError` {} and saving stays off (never overwritten). Saves/claims are refused until the load answered (`loaded`). A second live session on the same account is evicted (its gift clock is stored first and the new load waits for that write). Changing identity stores the old identity's gift clock first.
- `saveProgress` (whole snapshot, debounced client-side; upsert, `username` from the roster, not the message). Fields (`PlayerDoc`): `cash` (0..`CURRENCY_MAX` 1e15), `wins` (int 0..1e9), `streak` (int 0..1e6), `xp` (ranked XP total, int 0..1e9), `rankClaimed` (rank-division rewards granted, int 0..`RANK_LEVELS_MAX` 64), `tag` (chat tag, `TAG_PATTERN` /^[A-Z ]{0,16}$/, "" = none), `tutorialDone`, `abilityHintDone` (booleans), `ability` (0..`ABILITY_MAX` 100), `cues` { cueId: count } (ids `ID_PATTERN`, whole counts 1..1e6, 0/negative/non-finite dropped, at most `CUES_MAX` 256), `cue` (equipped id or ""; when the save carries `cues` it must be a key of it, else dropped), `bag` [{ uid (`UID_PATTERN` /^[A-Za-z0-9_-]{1,24}$/), kind (`ID_PATTERN`), readyAt (ms, clamped 0..now+30 days) }] (lucky blocks; unique uids, at most `BAG_MAX` 200), `hotbar` [uid] (unique, at most `HOTBAR_MAX` 9; when the save carries `bag`, each must be a bag uid), `perks` [id] (one-off client claims, e.g. starter cue), `playtime` (s), `lastSeen` (ms; also stamped by the server on leave). Anything else is dropped; server-owned fields (spins, daily, track, gifts) are never read from it.
- Spin wheel (`src/spin.ts`, `SPIN_*`, unchanged from Bowling Roll): doc `spins`/`spinAt`; server -> `spins` { spins, nextAt, serverTime }; `spin` -> `spinResult` { ok, id, spins, nextAt, serverTime } or { ok: false, reason: "loading" | "none" }.
- Daily Reward + streak track (`src/daily.ts`, `test/Daily.test.ts`), server UTC clock. Doc fields (server-written only, `saveDaily`): `dailyDay` (days unlocked this cycle, 0..`DAILY_DAYS` 7), `dailyLast` (UTC day index of the last unlock), `dailyClaimed[]` (0-based days), `trackDays` (0..`TRACK_DAYS` 28), `trackClaimed[]` (`TRACK_MILESTONES` [8, 14, 21, 28] indexes). On load today unlocks (`rollDaily`: +1 day per new UTC day, capped; all claimed -> new cycle at day 1). dailyView = { unlocked, claimed, nextAt (next UTC midnight), serverTime, track: { days, claimed } }.
  - `daily` (view) after load and on `dailyRefresh` {} (re-rolls after midnight).
  - `claimDaily` { day } -> `dailyResult` { ok, day, reason?: "loading" | "locked" | "save", ...view }. Success also moves the track: trackDays = min(28, trackDays + 1) in the same write; if every milestone was already claimed the track restarts first (0, []).
  - `dailyUnlockAll` {} -> `dailyUnlockResult` { ok, reason?: "loading" | "done" (already all unlocked) | "save", ...view }: unlocks all `DAILY_DAYS` of this cycle (the client charged its cash before sending).
  - `claimTrack` { i } -> `trackResult` { ok, i, reason?: "loading" | "locked" (bad index or trackDays < milestone) | "claimed" | "save", ...view }.
  - Every result is ok only once stored; a failed write is rolled back in memory.
- Playtime gifts (`src/gifts.ts`, `test/Gifts.test.ts`): `GIFT_MINUTES` [5, 15, 30, 45, 60] = minutes played TODAY (UTC). Doc fields (server-written only): `giftDay` (UTC day index), `giftSecs` (whole s that day), `giftsClaimed[]` (indexes that day); another day's are reset on load. The room clock ticks every `GIFT_TICK_MS` (`tickGifts`): connected sessions accrue time (a dropped one awaiting reconnection does not); crossing UTC midnight resets secs/claimed (only time after midnight counts) and re-sends `gifts`. Stored about every `GIFT_SAVE_MS` (60 s), right after a reset, on claim and on leave (with `lastSeen`).
  - `gifts` { secs, claimed, day, nextResetAt (next UTC midnight ms), serverTime } after the load and on every reset.
  - `claimGift` { i } -> `giftResult` { ok, i, reason?: "loading" | "locked" (bad index or secs < GIFT_MINUTES[i]*60) | "claimed" | "save", secs, claimed, day, nextResetAt, serverTime } (the "loading" answer has no state). ok only once stored.
  - Test hook: `room.__addGiftSecsForTest(sessionId, secs)`; `room.tickGifts(nowMs)` drives the clock.
- Ability Spin (`src/abilities.ts`, `test/Abilities.test.ts`; client `src/abilities.js` mirrors the ids, rarity chances and rules): doc field `abilities` { slots [id x3, "" = empty], unlocked 1..3, locked [bool x3], equipped (slot), spins, pity (spins since the last Epic+, the 100th is forced Epic+), codes [redeemed] }, written by the server only (never by saveProgress / not in sanitize.ts), cleaned by `abilitiesFrom` (new player: Fire Shot in slot 1, `ABILITY_START_SPINS` 1). After the load: `abilities` (the state) for a player with an id, `{ local: true }` for a guest (its client runs the rules itself). Messages `abilitySpin` {}, `abilityBuy` { pack } (`ABILITY_PACKS` spins; the client charged its cash first), `abilityRedeem` { code } (`ABILITY_CODES`, any case, once), `abilityEquip` { slot }, `abilityLock` { slot, locked }, `abilityUnlockSlot` { slot } (the next slot only; the client charged its cash) -> `abilityResult` { ok, action, reason?: "loading" | "guest" | "busy" | "none" | "locked" | "pack" | "invalid" | "used" | "slot" | "save", id/slot/forced (spin), n (spins granted), state }. ok only once stored (a failed write is rolled back in memory); one action at a time per session ("busy").
- Leaderboards (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`wins`, `xp`), one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). `leaderboard` { boards: { wins|xp: [{ name, value }] }, ranks: { wins|xp: n | null } }, sent after each load and to everyone every `LEADERBOARD_EVERY_MS`. `connectDb` creates a descending index per stat.
- Roster (`PlayerState`, `src/rooms/schema/WorldState.ts`) and presence (`src/presence.ts`, `test/Presence.test.ts`, `test/Roster.test.ts`), relayed as sent, only bounded: `username`, `signedIn`, `pfp` (http(s) only, max `PFP_MAX_LEN`, "" = none), `x`/`y`/`z`/`yaw`/`speed` (`pose` { x, y, z, yaw, speed }, bounds `POSE_BOUNDS`, yaw wrapped to -PI..PI), `cue` (`ID_PATTERN` or "") and `tag` (`TAG_PATTERN`) from `loadout` { cue, tag }, `avatar` (`setAvatar` { avatar }, Bloxity look JSON, at most `AVATAR_MAX_LEN`, never parsed). Leftover from Bowling Roll: `race` { racing, distance } -> roster `racing`/`distance` (distance clamped 0..`DISTANCE_MAX`, 0 when not racing). Players panel: `wins` (uint32), `cash`, `rank` (0..`RANK_BADGE_MAX` 8) and `flag` (`FLAG_PATTERN` /^[A-Z]{2}$/ or "") from `stats` { wins, cash, rank, flag } (also join option `stats`; whole numbers clamped to the save ceilings). Emotes: `emote` { id } (`ID_PATTERN`, "" = stop) sets `emote` and bumps `emoteSeq` (uint16) so a repeat restarts on the others; at most one start per `EMOTE_GAP_MS` 250 per player (stops always pass).
- `src/constants.ts` bounds must cover the client's config (catalog ids match `ID_PATTERN`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100 for party play; no `seatCap`: the matchmaker sizes pods). Needs repo var/secret `LEGION_GAME_ID` (= `crazy-8-ball`) and secret `LEGION_DEPLOY_TOKEN`.
